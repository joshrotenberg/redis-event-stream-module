# First AWS smoke run: 2026-07-30

This run proved the disposable lab and result assertions end to end. It is one
short sample, not a capacity claim or a statistically significant comparison.

## Environment

- Region and zone: `us-west-2`, `us-west-2a`
- Server: `c7i.large`
- Load generator: `c7i.large`
- Redis/module image:
  `ghcr.io/joshrotenberg/redis-event-stream-module:0.4.0@sha256:1466a273fd64321ca3eba4447db3a16e2eb231be2afdb3a620c5cb2229be4db2`
- Load-generator image:
  `redis:8.8.0@sha256:234c902a2db49461a129e2d4aeff85b28cf20187ed274a67f6e50995fa713c7b`
- Workload per scenario: 1,000,000 `SET` requests, 50 clients, two load
  threads, 64-byte values, and a 100,000-key keyspace

## Results

| Scenario | Operations/s | Change from baseline | p50 | p99 | Forwarded | Lost | Dropped |
|---|---:|---:|---:|---:|---:|---:|---:|
| `s0` module not loaded | 137,912 | baseline | 0.335 ms | 0.487 ms | 0 | 0 | 0 |
| `s1` module loaded, `SET` filtered | 137,893 | -0.01% | 0.335 ms | 0.479 ms | 0 | 0 | 0 |
| `s2` capture every `SET` | 121,183 | -12.13% | 0.383 ms | 0.631 ms | 1,000,000 | 0 | 0 |

The `s1` result was effectively identical to the unloaded baseline in this
sample. Capturing and retaining every `SET` reduced throughput by about 12% and
raised p99 by 0.144 ms. The configured `MAXLEN` held `events:set` at 10,000
entries, while the module still reported all 1,000,000 events forwarded with
zero loss, drops, or handler panics.

The run completed all assertions, Terraform destroyed all 16 managed resources,
the state was empty, and authoritative EC2/IAM checks found no active instances,
volumes, roles, or instance profiles afterward.

## What this does not answer

This run does not locate saturation, separate stream-write cost from trimming,
measure server CPU or memory, test expirations, persistence, replicas, cluster
mode, long-duration behavior, or failure recovery. Those belong in the
subsequent performance-backlog experiments.
